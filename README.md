### Code stage Rémi Moysan

Pour utiliser le code, il faut déjà :
- Preprocess toutes les données journalières (non lissées) de CESM2 SLP/PSL_anom_LE2-1231.003.nc; data/SST/SST_anom_LE2-1231.003_T_regrid.nc etc. Les nouvelles données mensuelles sont alors data/SLP/PSL_anom_LE2-1231.003_1mo.nc, data/SST/SST_anom_LE2-1231.003_T_regrid_1mo.nc. Cela s'effectue avec stage_isir_jz/data_analysis/mensualisation.py (cf data_analysis/mensualisation.slurm).
- Calculer la PCA de la SLP sur NDJF avec stage_isir_jz/data_analysis/pca_on_slp.py pour obtenir un joblib de la forme IPCA_latent128_winter_months_11_12_1_2_87members_normalizeFalse_monthly_reduction_wgtTrue_slp_std467.02/best_pca_model.joblib. Dans les codes d'entraînement, `latent_dim` tronque ce modèle jusqu'à la `latent_dim` composante principale (si c'est un vae par contre il faut que ce soit exactement égal car on ne peut pas tronquer).
- Pour les entraînements les nécessitant, on peut aussi calculer la pca de la sst (data_analysis/pca_on_sst.py )ou des embeddings vae de slp (data_analysis/vae_on_slp.py)
- On peut ensuite lancer les fichiers d'entraînement de modèles linéaires, de CNN, de Vision Transformer, pour des entraînements simples ou des entraînements Optuna (optimisation des hyperparamètres et LOOCV). Il faut veiller néanmoins au choix de tous les paramètres argparse : mettre le bon path vers la PCA de SLP ou tout autre embedder, prise en compte de la pondération de la latitude ou non (être cohérent avec le choix analogue pour l'embedder) `lat_weight`, carte de SST centrée sur l'océan atlantique ou pas `roll_sst`. Le nombre qui suit slp_std dans l'embedder sert à normaliser approximativement (globalement) les cartes de SLP, c'est pas forcément très utile mais c'est le choix que j'avais fait pendant le stage. Il faut donc évidemment garder la division par le même facteur entre le dataset qui a servi à entraîner la PCA et le dataset qui l'utilise ensuite pendant l'entraînement (c'est fait automatiquement en cherchant dans le nom du embedder passé en argument). 

Les codes d'entraînement sont normalement bien compatibles avec l'entraînement sur des données journalières (il faut enlever alors `monthly_reduction`), avec un lissage glissant quelconque, à condition d'appeler les fichiers de données SLP/PSL_anom_LE2-1231.015_{duree_lissage}d.nc' etc. 

Pour chaque modèle (cnn dans le dossier `cnn`, linear models avec pénalité dans `linear_models`), on a :
- des codes associés à un entraînement simple, `main_with_shap.py` qui entraîne le modèle avec un certain nombre de visualisation, l'évalue à la fin dans l'espace des embeddings et sur les reconstructions (appels à `eval_{nom du modèle}_embedding.py` et à `eval_{nom du modèle}_spatial.py`), et fait une évaluation shap sur les membres de test (appel à `eval_{nom du modèle}_shap`). Des fichiers slurm avec les hyperparamètres optimaux peuvent être données dans `optimal_hyperparameters_slurm/`
- un dossier `optuna_embedding` contenant le code optuna optimisant les hyperparamètres (à sets de validation et de test fixés) `optuna_hyperparameters.py`et un optuna Grid Search sur le choix de 1 membre de validaiton et le choix de 1 de test `optuna_cross_loocv`, à run avec les hyperparamètres trouvés grâce au premier run optuna, les fichiers slurm utilisés pour les scripts LOOCV (avec les hyperparamètres optuna) sont dans `optuna_cross_loocv_slurm_files`. Il y a également des fichiers en plus dans le cas du CNN car le début de l'étude de la distribution du Skill Score par membre par rapport au théorème central limite avait été commencé pour ce modèle. Les métriques optimisées (au choix) par optuna concerne des métriques sur des embeddings fixés : par exemple, corrélation de la NAO sur la validation.
- un dossier `optuna_spatial`avec la même chose mais pour optimiser les hyperparamètres puis faire la LOOCV avec des métriques spatiales (= sur l'image de SLP reconstruite), donc le code Optuna explore en plus comme hyperparamètres le nombre de composantes principales de SLP à garder / le choix du vae. 

Les dossier `vision_transformer` et `mlp` ont également en partie cette arborescence par modèle.

Le dossier `data_analysis` contient d'autres codes de certaines visualisations classiques et statistiques sur CPU, dont les composites, la régression linéaire sur le nombre de modes PCA/MCA optimal en entrée et en sortie `regression_pca_mca_modes.py`et l'approche PLS `partial_least_squared.py`.

Enfin, le dossier `shared_tools` contient tous les utilitaires communs à tous les modèles : fonctions de visualisation, classe Dataset, etc.
