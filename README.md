### Code stage Rémi Moysan

Pour utiliser le code, il faut déjà :
- preprocess toutes les données journalières (non lissées) de CESM2 SLP/PSL_anom_LE2-1231.003.nc; data/SST/SST_anom_LE2-1231.003_T_regrid.nc etc. Les nouvelles données mensuelles sont alors data/SLP/PSL_anom_LE2-1231.003_1mo.nc, data/SST/SST_anom_LE2-1231.003_T_regrid_1mo.nc. Cela s'effectue avec stage_isir_jz/data_analysis/mensualisation.py (cf stage_isir_jz/data_analysis/mensualisation.slurm).
- Calculer la PCA de la SLP sur NDJF avec stage_isir_jz/data_analysis/pca_on_slp.py pour obtenir un joblib de la forme IPCA_latent128_winter_months_11_12_1_2_87members_normalizeFalse_monthly_reduction_wgtTrue_slp_std467.02/best_pca_model.joblib. Dans les codes d'entraînement, `latent_dim` tronque ce modèle jusqu'à la `latent_dim` pca (si c'est un vae par contre il faut que ce soit exactement égal car on ne peut pas tronquer).
- Pour les entraînements les nécessitant, pon peut aussi calculer la pca de la sst (stage_isir_jz/data_analysis/pca_on_sst.py )ou des embeddings vae de slp (stage_isir_jz/data_analysis/vae_on_slp.py)
- On peut ensuite lancer les fichiers d'entraînements de modèles linéaires, de CNN, de Vision Transformer, pour des entraînements simples ou des entraînements Optuna (optimisation des hyperparamètres et LOOCV). Il faut veiller néanmoins au choix de tous les paramètres argparse : mettre le bon path vers la PCA de SLP ou tout autre embedder, prise en compte de la pondération de la latitude ou non cohérent avec cette embedder `lat_weight`, carte de SST centré sur l'océan atlantique ou pas `roll_sst`. Le nombre qui après slp_std dans l'embedder sert à normaliser approximativement (globalement) les cartes de SLP, c'est pas forcément très utile mais c'est le choix que j'avais fait pendant le stage. Il faut donc évidemment garder la division par le même facteur pour diviser entre le dataset qui a servi à entraîner la PCA et le dataset qui l'utilise ensuite pendant l'entraînement, c'est fiat automatiquement en cherchant dans le nom du embedder passer en argument. 

Les codes d'entraînement sont normalement bien compatible avec l'entraînement sur des données journalières (il faut enlever alors `monthly_reduction`), avec un lissage glissant quelconque, à condition d'appeler les fichiers de données SLP/PSL_anom_LE2-1231.015_{duree_lissage}d.nc' etc. 

Pour chaque modèle (cnn, linear models avec pénalité, vision transformer):
- des codes associés à un entraînement simple, `main_with_shap.py` qui entraîne le modèle avec un certain nombre de visualisation, l'évalue à la fin dans l'espace des embeddings et sur les reconstructions (appels à `eval_{nom du modèle}_embedding.py` et à `eval_{nom du modèle}_spatial.py`), et fait une évaluation shap sur les membres de tests (appel à `eval_{nom du modèle}_shap`). Des fichiers slurm avec les hyperparamètres optimaux peuvent être données dans `optimal_hyperparameters_slurm/`
- un dossier `optuna_embedding` contenant le code optuna optimisant les hyperaparamètres (à set de validation et de test fixé) `optuna_hyperparameters.py`et un optuna Grid Search sur le choix de 1 membre de validaiton et le choix de 1 de test `optuna_cross_loocv`, à run avec les hyperparamètres trouvé grâce au premier run optuna, les fichiers slurm utilisé pour les scripts LOOCV (avec les hyperparamètres optuna) sont dans `optuna_cross_loocv_slurm_files`. Il y a également des fichiers en plus dans le cas du CNN car le début de l'étude de la distribution du Skill Score par membre par rapport au théorème centrale limite avait été commencé pour ce modèle.
